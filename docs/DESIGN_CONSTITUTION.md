# 前端设计宪法（冻结版）

本文件冻结的是**形态决策**，不是配色。改动前先读它。

## 零、为什么需要这份文件

git 历史上已经做过三轮视觉重做：`Apple 语义 + Notion 暖中性` → `ChatGPT 双色玻璃` →
当前 v3。三轮改的全是色板，版式一次没动，而不满意感也没有消失。

结论：痛点不在色板，在形态。**色板自本文件起冻结，不再做第四轮。**

## 一、产品形态事实（一切决策从这里出发）

| 事实 | 证据 |
|---|---|
| 内容本体是 9:16 竖屏 | `player_view.dart` 已按 `aspectRatio: 9 / 16` 渲染竖屏版 |
| 单集极短，观感是「刷」 | 播放器已做上滑切下一集手势 |
| 一部 60–100 集，选集是高频交互 | `detail_view.dart` 的分组集条 / 集网格 |
| 封面自带标题党文案，是唯一卖点 | 红果源封面即标题板 |
| 用户决策窗口约 3 秒 | 短剧品类的通用行为特征 |

推论：**首页不能用番剧聚合（Kazumi）的海报墙**。番剧是横屏内容、单集 24 分钟、
用户愿意先看简介再决定；短剧是竖屏、单集几分钟、靠封面三秒内决定。

## 二、六条铁律

1. **封面不裁切。** 一律按 cover 原始比例渲染，禁止 `AspectRatio` 强制成 2:3 后
   `fill: true` 裁切。裁掉的就是封面上的卖点文案。
2. **内容即界面。** 凡封面或画面出现的地方，chrome 让位：文字叠在封面下缘的
   scrim 上，不另起一行放在封面下方。
3. **一屏只回答一个问题。** 首页回答「我现在该看什么」，榜单回答「大家在追什么」，
   追剧回答「我追的更新了吗」。不要在一屏里塞第二件事。
4. **分层靠排版与负空间，不靠边框和容器色。** 卡片默认无描边、无阴影、无容器色差；
   分组靠间距（≥ 24），分隔只在必要时用发丝线。`cardTheme` 里的 1px 描边是
   Material 胎记，移除。
5. **玻璃只在有东西可折射的地方出现。** 详见第三节。
6. **续播做进卡片。** 首页不做横滑区（信息密度优先）。看过的卡右上角带
   「继续看 第N集」白胶囊 + 下缘发丝进度线——不靠横滑区也能找到续播入口。

## 三、液态玻璃的位置表

玻璃的物理意义是折射它下面的东西。铺在纯色底上，模糊采样到的全是一片白，
渲染结果就是一块发灰的脏斑——再叠 `saturation` 只会更脏。

用量档位：**中等——导航栏 + 画面之上的控件**。

**允许：**

| 位置 | 底下是什么 |
|---|---|
| 底部 Tab 栏 | 从它下方滚过的封面流 |
| 详情页顶栏三枚圆钮 | 高斯模糊后的海报 |
| 播放器控件（竖屏互动栏 / 横屏控制条） | 视频画面（效果最好） |
| 首页顶栏（**仅在滚动越过阈值后**） | 已滚过的封面流 |
| 侧栏（平板 / 桌面档） | 内容区从它右侧经过 |

**禁止：**

- 停在顶部的首页顶栏——底下是纯白，没有折射对象。改为：停顶时完全透明，
  滚动超过阈值后才浮起玻璃。
- **搜索框**——它随内容一起滚动，不常驻，底下是纯色。用 `mist` 浅雾底圆角槽。
- 追剧页的**分段控件**——它在纯色底上。用 `mist` 浅雾底 + 白色滑块（iOS 原生形态）。
- 列表卡、海报卡、任何内容层元素。
- 玻璃内再嵌玻璃（静默降质，不报错，最难发现）。

## 四、无彩色界面 + 封面取色

- **界面色板彻底无彩色**：只有黑 / 白 / 两级灰 / 发丝线 / 浅雾。没有强调色。
- **颜色唯一来源是封面。** 详情页与播放器的氛围色从封面主色提取
  （Apple Music / Apple TV 的做法）：背景 = 封面放大 1.15 + blur 52px + 径向
  氛围色，向下 58% 处渐隐回底色。
- **主操作是墨色胶囊** `textPrimary` + `onInk`。没有彩色按钮。
- 状态与进度用**灰度与字重**表达，不使用彩色。
- 对比度纪律不变，`test/token_contrast_test.dart` 继续作为回归防线
  （需重写：原断言里有大量 `#10A37F` 相关项，色板无彩后应改为灰阶断言）。

## 五、卡片密度（连续公式，对齐 Kazumi）

Kazumi 有两种做法：首页是硬编码断点（`3 / >600 → 5 / >840 → 6`），
搜索结果是连续公式 `max(2, floor(width / 180))`。本项目统一采用**连续公式**，
因为它在大屏上不会突然跳列：

```dart
/// 目标卡宽 140pt；下限 3 列（手机），上限 8 列（超宽屏）。
int feedColumns(double availableWidth) =>
    (availableWidth / 140).floor().clamp(3, 8);
```

`availableWidth` = 窗口宽 − 侧栏占位 − 左右 gutter，其中**侧栏占位 = 侧栏宽 + 24**
（浮起玻璃片左侧留 12、与内容之间再留 12；手机档无侧栏，占位 0）。gutter：
手机 16 / 平板 24 / 桌面 34。以下为原型实测值：

| 档位 | 窗口宽 | 侧栏占位 | gutter×2 | 可用宽 | 计算 | 列数 | 单格 |
|---|---|---|---|---|---|---|---|
| 手机 | 390 | 0 | 32 | 358 | 2.56 → clamp | **3** | 111pt |
| 平板 | 834 | 224 | 48 | 562 | 4.01 | **4** | 132pt |
| 桌面 | 1280 | 264 | 68 | 948 | 6.77 | **6** | 149pt |

封面比例 **3:4**（Kazumi 用 0.7，即高宽比 1.43；短剧封面实际以 3:4 为主，
且 3 列时 1.33 的高度更省纵向空间）。

## 六、首页形态（终稿，与原型一致）

1. 全屏就是一张竖卡网格，**无横滑区、无 banner、无分区头条**。
2. 封面按原始比例 3:4 渲染，禁止 `AspectRatio` 强制裁切。
3. 标题与集数叠在封面下缘 scrim 上，卡片不再有独立文本区。
4. 列数走上面的 `feedColumns`，手机固定落在 3 列。
5. 顶部无独立顶栏，只有大标题「发现」+ 两枚玻璃圆钮（搜索 / 切换源）；
   滚动时大标题缩到 17px 居中、栏体才浮起玻璃。
6. `cardTheme` 移除 `BorderSide` 描边；列表行间只用 0.5px 发丝线。

## 七、搜索页：筛选优先（对齐 Kazumi，无热门趋势）

**不显示热门趋势。** 搜索页只承担筛选与展示两件事。

- **本页没有导航**（见第八节），所以**搜索框左侧自带一枚返回圆钮**（浅雾底，
  不是玻璃——它在纯色上）。不设常驻顶栏。
- **引导态**：搜索框（44px 浅雾底圆角槽）+ 「按条件筛选」主入口
  （副标题「题材、状态、集数与排序」）+ 最近搜索（可管理 / 清空）。
- **结果态**：同上搜索框随内容滚动；「搜索结果」+ 计数「N 部剧集」+ 排序菜单 +
  筛选钮（有筛选生效时带 Badge）+ 一行筛选摘要；网格复用 `feedColumns`。
- **筛选维度（短剧场景，不是番剧的放送季度 / 评分）**：题材（多选）、
  状态（全部 / 连载中 / 已完结）、集数区间、排序、内容源。
- 内容最大宽：引导态 760、结果态 1120（Kazumi 同值），居中留白。

## 八、导航三档（按宽度；且必须是 iOS 语言，不是 Material 组件）

**先明确不要什么。** `NavigationBar` / `NavigationRail` 是 Material 组件，照搬会把
Material 的导航语言一起带进来。`NavigationRail` 那种 78pt 竖排图标条在 iOS 上根本
不存在——iPadOS 的侧栏是常显「图标 + 文字」的宽栏（≥ 220pt）。本项目按 iOS 表达：

- **选中态 = 图标由线稿切换为实心**（SF Symbols 的 outline → fill）+ 文字着色加粗。
  不做选中胶囊、不做指示器圆点、不做图标下方小横条——那些都是 Material 的语言。
- **底部 Tab 条 = 浮起玻璃胶囊**（iOS 26）：不贴屏幕底边，左右内缩 14，高 60，圆角 30。
- **侧栏 = 浮于内容之上的一层圆角矩形液态玻璃。** 关键：它是**一片浮起的玻璃**，
  不是「一条竖切到顶到底的颜色块」——不贴屏幕边（左 12 / 上 12 / 下 12）、
  四角 26 圆角、带 `box-shadow` 投影以表达层级。内容从它右侧让开 12。
  常显图标 + 文字，选中为圆角填充 + 字重 600。

| 档位 | 宽度 | 导航 | 规格 |
|---|---|---|---|
| compact | < 600 | 浮起玻璃 Tab 条 | 高 60，内缩 14，圆角 30，4 项，线稿/实心切换 |
| medium | 600–1023 | 浮起玻璃侧栏 | 宽 200，内缩 12，圆角 26，搜索行 + 4 项 + 底部设置 |
| expanded | ≥ 1024 | 浮起玻璃侧栏 | 宽 240，内缩 12，圆角 26，品牌行 + 搜索行 + 4 项 + 底部设置 |

**导航只出现在四个 Tab 页。** 其余页面（搜索 / 详情 / 播放器）一律
**不显示任何导航**——底部 Tab 条和侧栏一起撤掉，整屏交给内容，返回靠
左上角的圆钮（`hidesBottomBarWhenPushed` 的语义，扩展到侧栏档）：

| 页面 | 导航 | 返回方式 |
|---|---|---|
| 发现 / 榜单 / 追剧 / 我的 | 显示（Tab 条 或 侧栏） | — |
| 搜索 | **无** | 搜索框左侧返回圆钮 |
| 详情 | **无** | 顶栏左上角玻璃圆钮（浮在模糊海报上，玻璃成立） |
| 播放器 | **无** | 左上角圆钮（浮在画面上，玻璃成立） |

> 这条**取代**了上一版「侧栏档保留详情页侧栏」的规则。原规则的理由是
> 「侧栏是窗口级导航、不属于 push 栈」，但实测下来它带来两个问题：
> 一是侧栏压在纯色内容页上会发灰（没有折射对象），二是详情页本该是沉浸页，
> 窗口级导航常驻会抢走封面取色营造的氛围。现在统一为：**只有四个 Tab 页有导航。**

**侧栏玻璃的已知代价（接受）：** 四个 Tab 页的正文基本是纯色底，侧栏玻璃在这里
采样不到东西，会略偏灰。之所以仍然保留玻璃，是因为侧栏下方会经过封面网格的边缘、
以及滚动时的封面流——移动端之外内容区普遍更宽，折射对象的覆盖率够。
原型里的「玻璃 开/关」开关就是用来对照这个代价的；若最终判定不可接受，
退路是把侧栏降为 `mist` 浅雾底（保留浮起圆角矩形形态与投影，只去掉模糊）。

## 九、停止重构的机制

任何视觉改动动工前，先回答这三个问题，答不上来就不改：

1. 这次改的是**形态**还是**色板**？改色板 → 不做。
2. 改动是否让「找到下一部能看的剧」更快？没有 → 不做。
3. 改完后有 golden test 锁住吗？没有 → 先补测试再改。

版式改动一律配 golden test（首页窄/中/宽三档），把「现在这样是对的」
固化成断言，避免下一次重构又推翻它。
